# レコードの読み方

**JV-Data の1レコードは、区切り文字のない固定長のバイト列です。**
どこからどこまでが何の項目かは、仕様書の位置表を見るしかありません。

このページは、実際に受け取った1レコードを最初から最後まで解きます。

## 実物で読む

`RACE` を取得したときに `JVGets` が返した `RA`（レース詳細）レコードの先頭28バイトです。

```
RA72026083120260829010203011
```

仕様書「２．レース詳細」の位置表に当てると、こう切れます。

| 位置 | バイト | 値 | 項目名 | 意味 |
| ---: | ---: | :--- | :--- | :--- |
| 1 | 2 | `RA` | レコード種別ID | レース詳細である |
| 3 | 1 | `7` | データ区分 | 7 = 成績（月曜） |
| 4 | 8 | `20260831` | データ作成年月日 | 2026年8月31日に作られた |
| 12 | 4 | `2026` | 開催年 | ← キー |
| 16 | 4 | `0829` | 開催月日 | ← キー |
| 20 | 2 | `01` | 競馬場コード | 01 = 札幌競馬場。← キー |
| 22 | 2 | `02` | 開催回[第N回] | 第2回。← キー |
| 24 | 2 | `03` | 開催日目[N日目] | 3日目。← キー |
| 26 | 2 | `01` | レース番号 | 1R。← キー |
| 28 | 1 | `1` | 曜日コード | 1 = 土曜日 |

**つまり「2026年8月29日、札幌2回3日目の1R、月曜に確定した成績」です。**
残りの1,244バイトに、レース名・距離・馬場状態・払戻対象などが続きます。

全項目は [reference/RA.md](reference/RA.md) にあります。

## どのレコードも先頭3項目は同じ形

**種別が違っても、先頭の3項目は必ず同じ並びです。** ここだけ覚えれば、
未知のレコードでも「何で、いつ作られたか」は読めます。

| 位置 | バイト | 項目名 | 何が入るか |
| ---: | ---: | :--- | :--- |
| 1 | 2 | レコード種別ID | `RA` `SE` `UM` など。**これでテーブルが決まります** |
| 3 | 1 | データ区分 | どの段階の情報か。後述 |
| 4 | 8 | データ作成年月日 | `yyyymmdd` |

その後ろにキー項目が並び、最後は必ず**レコード区切**（CR/LF の2バイト）で終わります。

## 文字コード

**全角は Shift_JIS、半角は JIS8 の1バイトです。**

そのため、**バイト位置で切る前に文字列へ変換してはいけません。** 全角文字は2バイトを
食うので、`str` に直してから数えると位置がずれます。受信データは `bytes` のまま扱い、
切り出したあとで `cp932` として復号します。

```python
# 正しい
raw[11:15].decode("cp932")     # 開催年

# 間違い（全角を含む項目があると位置がずれる）
raw.decode("cp932")[11:15]
```

## 「キー」は仕様書が指定しています

位置表の「キー」列に `○` が付いた項目が、**JRA-VAN が推奨する主キー**です。
自分で選ぶものではありません。

仕様書には、こう明記されています。

> JRA-VAN Data Lab. で提供される JVData のレコード収録順序には仕様はありません
> 事前の告知なく収録順序が変わることがありますのでデータベースに反映させる場合には、
> キー項目や、データ作成日を利用してください。

**「何番目に来たか」を当てにしてはいけない**、ということです。

レコードごとのキーは [レコード索引](reference/index.md) にまとまっています。
よく使うものだけ挙げます。

| 種類 | キー | 使う表 |
| :--- | :--- | :--- |
| レースキー | 開催年 + 開催月日 + 競馬場コード + 開催回 + 開催日目 + レース番号 | RA HR H1 H6 O1〜O6 TK DM TM |
| 出走キー | レースキー + 馬番 + 血統登録番号 | SE |
| 馬 | 血統登録番号 | UM SK HY |
| 人 | 騎手コード / 調教師コード / 馬主コード / 生産者コード | KS CH BN BR |

## データ区分 — 同じレースが何度も届く

**JV-Data は、1つのレースについて同じキーのレコードを何度も配信します。**
木曜の出馬表から月曜の確定成績まで、情報が更新されるたびに届きます。

どの段階かを示すのが「データ区分」です。`RA` の場合はこうです。

| 値 | 意味 | いつ |
| :--- | :--- | :--- |
| `1` | 出走馬名表 | 木曜 |
| `2` | 出馬表 | 金・土曜 |
| `3` | 速報成績（3着まで確定） | レース直後 |
| `4` | 速報成績（5着まで確定） | 〃 |
| `5` | 速報成績（全馬着順確定） | 〃 |
| `6` | 速報成績（全馬着順＋コーナ通過順） | 〃 |
| `7` | **成績（確定）** | 月曜 |
| `A` | 地方競馬 | |
| `B` | 海外国際レース | |
| `9` | レース中止 | |
| `0` | **該当レコード削除**（提供ミスなど） | |

値の意味はレコード種別ごとに違います。各レコードの項番2を見てください。

> [!CAUTION]
> **素朴に追記すると同じレースが9行になります**
>
> **上書きの判定が要ります。** `データ作成年月日` と `データ区分` を組み合わせて
> 新旧を比べ、新しい方だけを残します。本ツールがどう実装しているかは
> [README の「同じデータを2回取り込んでも行が増えない理由」](https://github.com/ht-0328/jvdata-store#同じデータを2回取り込んでも行が増えない理由)
> に、実データ付きで書いてあります。
>
> `0`（削除）の扱いには注意が要ります。**行を消すのではなく、削除済みとして残します。**
> 消してしまうと、古いファイルを読み直したときに復活してしまうためです。

## 繰返しブロック

**1レコードの中に、同じ形の項目が何度も並ぶことがあります。** 2種類あります。

### 内訳を持つもの（子テーブルにする）

`TK`（特別登録馬）の `<登録馬毎情報>` は、70バイトの塊が300回繰り返します。
中に連番・血統登録番号・馬名などが入っています。

これを横に並べると列数が破綻します。実際、仕様書のまま展開するとこうなります。

| レコード | 仕様書のまま | 親テーブルにすると |
| :--- | ---: | ---: |
| `H6` 票数6（3連単） | 14,720列 | 34列 |
| `O6` オッズ6（3連単） | 14,702列 | 15列 |
| `TK` 特別登録馬 | 3,036列 | 37列 |

**そこで、繰返しブロックは子テーブルに分けます。** 子テーブルのキーは
「親のキー ＋ 連番」です。

```
tk                   レースキー + 特別競走番号など        (37列)
tk__登録馬毎情報      レースキー + _連番 + 血統登録番号…   (11列)
```

### 内訳を持たないもの（連番列にする）

`RA` の `本賞金` は8バイトが7回繰り返すだけで、内訳がありません。
これは子テーブルにせず、`本賞金_1` 〜 `本賞金_7` という列に展開します。

どちらになるかは、各レコードの参照ページに書いてあります。

## 初期値の記号

位置表の「初期値」列は、**値が無いときに何で埋まるか**を示します。

| 記号 | 埋まるもの |
| :--- | :--- |
| `0` | 半角数字の `0` |
| `sp` | 半角スペース |
| `Ｓ` | 全角スペース |
| `Ｓ sp` | 全角と半角のスペースが混在 |

**「0 で埋まっている」と「本当に 0 である」は区別できません。** 未設定かどうかは、
関連する項目やデータ区分から判断することになります。

## 値は桁のまま持つ

**コード値も数値も、仕様書の桁のまま文字列として持つのが安全です。**

| 項目 | 生の値 | 意味 | 数値化すると |
| :--- | :--- | :--- | :--- |
| 競馬場コード | `01` | 札幌 | `1` になり[コード表](reference/codes.md)と突き合わせられない |
| 単勝オッズ | `0054` | 5.4倍 | 小数点の位置は項目ごとに違う |
| 距離 | `1600` | 1600m | これは数値でよい |

オッズ・タイム・重量は、それぞれ単位と小数点位置が違います。項目の説明に
「単位:0.1kg」「99.9秒」のように書かれているので、**変換は読む側で、
用途に合わせて行う**のが安全です。
