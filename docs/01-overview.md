# JV-Data の全体像

**JV-Data は、JRA-VAN が配信する競馬データの総称です。** 中身は固定長のテキストレコードで、
JV-Link という COM コンポーネント経由でしか受け取れません。

このページでは、受け取るまでの全体像を押さえます。個々のレコードの中身は
[レコードの読み方](02-record-format.md) で扱います。

## 覚える言葉は3つだけです

混乱の元は、似た名前の「ID」が2種類あることです。**役割がまったく違います。**

| 言葉 | 例 | 何を指すか | 誰が使うか |
| :--- | :--- | :--- | :--- |
| **データ種別ID** | `RACE` `DIFN` `0B41` | **取得の単位。** 「レース情報をくれ」と頼むときの名前 | `JVOpen` に渡す |
| **レコード種別ID** | `RA` `SE` `UM` | **中身の型。** 1レコードが何の情報かを示す名前 | レコードの先頭2バイト |
| **ファイル** | `RASW2026082920260831133220.jvd` | 配信の物理単位。複数レコードが入る | 意識しなくてよい |

関係はこうです。

```
データ種別ID  RACE （レース情報をください）
   └─ ファイル  RASW2026082920260831133220.jvd
   |     └─ レコード  RA…（8月29日1R）
   |     └─ レコード  RA…（8月29日2R）… 36レース分
   └─ ファイル  SESW2026082920260831133222.jvd
         └─ レコード  SE…（1R 1番の馬）…
```

**1つのデータ種別IDが、複数のレコード種別を含みます。** `RACE` を頼むと
`RA`（レース詳細）だけでなく `SE`（馬毎レース情報）も `HR`（払戻）も届きます。
どの種別に何が含まれるかは [データ種別と提供タイミング](03-dataspecs.md) にあります。

> [!TIP]
> **ファイル名は気にしなくてよい**
>
> JV-Link はファイルの区切りを隠してくれます。`JVGets` を呼び続けるだけで、
> 複数ファイルが1本の列として流れてきます。**そもそも仕様書はファイル名の書式を
> 定義していません。** 依存しないでください。

## 蓄積系と速報系

**この2つは提供期間がまったく違います。設計に直接効きます。**

| | 蓄積系 | 速報系 |
| :--- | :--- | :--- |
| 何のためか | 過去のデータを貯める | 当日の変化を追う |
| 呼び出し | `JVOpen` | `JVRTOpen` |
| 指定するもの | **期間**（いつ以降か） | **キー**（どのレース／どの日か） |
| 提供期間 | 通常データは1年、それ以前はセットアップ | **1週間**（時系列オッズだけ1年） |
| データ種別IDの形 | `RACE` `DIFN` など英字4文字 | `0B15` `0B41` など英数4文字 |

> [!CAUTION]
> **速報系は1週間で消えます**
>
> 馬体重・天候馬場状態・出走取消・騎手変更・発走時刻変更・コース変更の6レコードは、
> **速報系でしか配信されません。** 過去に遡って取ることはできません。
> 必要なら、当日に取って自分で貯めるしかありません。
>
> 例外は時系列オッズ（`0B41` 単複枠・`0B42` 馬連）で、**提供期間が1年あります**。
> 過去1年のレースなら、5分刻みの発走前オッズを後から取れます。

## 過去に遡る2つの経路

蓄積系には、同じデータに2つの取り方があります。`JVOpen` の `option` で選びます。

| option | 名前 | どこまで遡れるか | いつ使うか |
| ---: | :--- | :--- | :--- |
| 1 | 通常データ | **1年** | 前回の続きを取る |
| 2 | 今週データ | 直近の開催のみ | 今週だけ欲しいとき |
| 3 | セットアップ | 1年より前も可 | 初回。ダイアログが出る |
| 4 | ダイアログ無しセットアップ | 同上 | 初回。2回目以降は自動 |

**初回は必ずセットアップ（3か4）を通ります。** 通常データはサーバに1年しか置かれないので、
それより前は取れないからです。

> [!TIP]
> **どこまで遡れるかは仕様書に書いてあります**
>
> JV-Data仕様書の「データ種別一覧」シート、**（３）セットアップデータ**の節に、
> レコードごとの収録開始時期が明記されています。レース詳細は1986年以降、
> 3連単オッズは2004年8月以降、というように**レコードごとに違います**。
>
> 一覧は [データ種別と提供タイミング](03-dataspecs.md#セットアップで遡れる範囲) に
> まとめました。**遡れる範囲を見積もるときは、必ずこの表を見てください。**

## 取得の流れ

JV-Link の呼び出し順序は決まっています。インターフェース仕様書のとおりです。

```
JVInit("ソフトウェアID")          ← 最初に1回だけ
  │
  ├─ JVOpen(種別, 期間, option)   ← 蓄積系。対象ファイル数が返る
  │    └─ JVStatus()              ← ダウンロードの進捗を見る
  │
  ├─ JVRTOpen(種別, キー)          ← 速報系。こちらは期間ではなくキー
  │
  ├─ JVGets(buff, size)  ×N       ← 1回で1レコード。0 が返るまで繰り返す
  │       戻り値 >0 : 読んだバイト数
  │       戻り値 -1 : ファイルの切り替わり（エラーではない）
  │       戻り値 -3 : まだダウンロード中。待って再試行
  │       戻り値  0 : 全部読み終わった
  │
  └─ JVClose()                    ← Open したら必ず呼ぶ
```

> [!NOTE]
> **`-1` と `0` を取り違えないこと**
>
> ファイルの切り替わりでも `-1` が返ります。**エラーではありません。**
> 全ファイルを読み終わると、`-1` が1回返ったあと、次の呼び出しで `0` が返ります。
